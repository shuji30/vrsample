# vrsample — 窓の外に公園のある部屋

three.js + WebXR でつくった、**ビルド不要**の VR サンプルです。
`index.html` を配信するだけで動きます（バンドラも npm install も不要）。

木の床に丸テーブルと椅子、ソファ、本棚のある部屋です。左の窓から日が差して
床に光の帯を落とし、正面の大きな窓の外には**さるすべりの木と滑り台のある公園**が
広がっています。右の壁のスイッチで昼 / 夕 / 夜が切り替わります。
**VRM のキャラクター**が部屋をゆっくり歩きまわり、ときどきソファに腰かけます。
呼吸とまばたきをしながら、こちらを目で追います（[キャラクター（VRM）](#キャラクターvrm)）。

- ヘッドセット（Meta Quest など）のブラウザ → 「ENTER VR」で没入
- PC / スマホのブラウザ → そのまま 3D シーンとして操作できる

**部屋のほうは 3D モデルもテクスチャ画像も 1 枚も持っていません。**床の木目も
壁の塗りムラもさるすべりの樹皮も、すべて起動時にコードで焼いています
（`src/textures.js`）。クローンしてすぐ動き、オフラインでも回線が細くても
影響を受けません。外から持ち込むアセットは `models/character.vrm`（キャラクター）
だけで、これも無ければ部屋はそのまま動きます。

## 動かす

```bash
git clone <このリポジトリ> && cd vrsample
npm start          # http://localhost:8080 で配信（依存パッケージなし）
```

`npm start` は `scripts/serve.mjs`（Node 標準モジュールだけの静的サーバー）を起動します。
`python3 -m http.server 8080` など、他の静的サーバーでも構いません。

> **ファイルを直接開く（`file://`）のは不可** です。ES modules と importmap を使っているため、
> HTTP で配信する必要があります。

起動時に 1〜2 秒ほど「部屋を焼いています…」と出ます。内訳はテクスチャ生成（CPU、
実測 0.7 秒ほど）と環境マップの焼き込み（GPU）です。`?quality=0.5` にすると
テクスチャ生成は 0.2 秒ほどに縮みます。

## Pimax（PCVR）で試す

Pimax は PC に繋いで使うヘッドセットなので、Quest のように「ヘッドセット内のブラウザ」で
開くのではなく、**PC のブラウザから VR に入ります**。HTTPS 化も不要で、いちばん手順が短いです。

1. **Pimax Play を起動**し、ヘッドセットが認識されている状態にする。
2. **OpenXR ランタイムをどちらか一方に確定させる。**
   Pimax Play → デバイス設定 → 一般 で Pimax / Steam を選べます。SteamVR 側から設定するなら
   SteamVR → 設定 → OpenXR → 「SteamVR を OpenXR ランタイムに設定」。
   どちらでも動きますが、**アクティブなランタイムが 1 つに決まっていること**が必要です。
3. 同じ PC で `npm start`。
4. **Chrome か Edge**（Chromium 系）で `http://localhost:8080` を開く。
   Windows の Chrome の WebXR は OpenXR 経由なので、これだけで「ENTER VR」が押せます。
   `localhost` はセキュアコンテキスト扱いなので HTTPS は不要です。

> Firefox デスクトップは WebXR に対応していないので使えません。Chrome / Edge を使ってください。

### 「GPU が上の PC のほうが重い」とき

VR に入る前の画面の重さは、**GPU の性能よりも塗るピクセル数**でほぼ決まります。
`?perf` を付けると右下に実測が出るので、2 台の PC で見比べてください。

```
58 fps
3840x2160 (8.3Mpx) dpr 2.00
NVIDIA GeForce RTX 4070 ...
```

見るべきは 3 行とも。よくある原因は次の 3 つです。

1. **dpr（devicePixelRatio）が違う。** 4K ディスプレイを 150〜200% 表示で使っていると
   dpr が 1.5〜2 になり、ウィンドウの見た目が同じでも**塗る量が 2〜4 倍**になります。
   高性能な GPU を積んだ PC ほど大きく高精細なディスプレイを繋いでいることが多いので、
   これが「性能が上なのに重い」の正体になりがちです。`?dpr=1` で揃えて比べられます。
2. **GPU の名前が想定と違う。** ノート PC の場合、Chrome が内蔵 GPU で動いていることが
   あります。`Intel(R) UHD Graphics` などと出ていたら、Windows の
   設定 → システム → ディスプレイ → グラフィック で Chrome を「高パフォーマンス」に
   割り当ててください。`SwiftShader` や `Microsoft Basic Render Driver` と出ていたら
   ハードウェアアクセラレーションが無効です（`chrome://gpu` で確認）。
3. **リフレッシュレートが違う。** 144Hz のディスプレイでは描画ループが 144fps を
   目標にするので、60Hz 機より 2.4 倍の仕事をします。

```
http://localhost:8080/?perf          # 右下に fps / 解像度 / GPU を出す
http://localhost:8080/?perf&dpr=1    # 解像度の条件を揃えて比べる
```

### 開けないとき

まず**画面下の状態表示**を読んでください。起動の各段階（「部屋を焼いています…」→
「操作の準備中…」→ 検出結果）と、失敗した場合はその段階とエラーメッセージが
そのまま出ます。ヘッドセットで試すときに DevTools を開かずに済ませるためです。

次に `?safe` を付けて開き直します。影・環境マップ・テクスチャ解像度・XR の
レンダー解像度をすべて最小にしたモードで、これで開けるなら原因は描画負荷側、
開けないなら WebXR 側の問題だと切り分けられます。

```
http://localhost:8080/?safe
```

### ENTER VR が出ない・押しても始まらないとき

- アクティブな OpenXR ランタイムが決まっているか（手順 2）。Pimax Play と SteamVR を
  両方立ち上げていると取り合いになることがあります。
- Chrome を `--disable-features=XRSandbox` 付きで起動してみる。XR サンドボックスが
  原因で immersive session に入れない既知のケースがあります（セキュリティ機能を落とすので
  常用はしないこと）。
- `chrome://gpu` で WebGL / ANGLE が有効か確認する。

**「There is already an active, immersive XRSession」と出るとき**は、そのブラウザで
すでに VR セッションが開いています。別のタブ / ウィンドウで同じページ（や他の
WebXR サイト）を開いていないか確認し、そちらで VR を終了してください。VR 中に
リロードしたあとにも起きることがあり、その場合はブラウザを開き直すと戻ります。

> ちなみに three.js の `VRButton` は `requestSession` が返るまで内部の
> `currentSession` が null のままなので、**返事を待たずに ENTER VR をもう一度押すと
> 自分で 2 本目のセッションを要求して**この状態になります。`src/main.js` で
> 二度押しを握りつぶし、失敗も拾って画面に出すようにしてあります（`VRButton` 側に
> `catch` が無く、そのままだと未処理の Promise 拒否として出るだけなので）。

### Parallel Projections は ON にしなくてよい

Pimax は左右のディスプレイが内向きに傾いています（canted display）。three.js の
`WebXRManager.setProjectionFromUnion()` は**左右の目が平行に向いている前提**でカリング用の
視錐台を 1 つに合成するため、傾いたディスプレイでは視錐台が実際より狭くなり、
視界の外縁でオブジェクトが早めに消えることがあります。

このシーンは数百オブジェクトあるのでカリング自体は効かせたまま、**各ジオメトリの
バウンディングスフィアを 1.35 倍に膨らませて**対処しています（`src/main.js`）。
Pimax Play の **Parallel Projections は OFF のままで大丈夫**です（ON にすると描画負荷が
3 割ほど増えます）。

```js
// src/main.js
if (!geometry.boundingSphere) geometry.computeBoundingSphere();
geometry.boundingSphere.radius *= 1.35;
```

それでも視界の縁が欠けるなら `?cull=off` でカリングを完全に切れます。

### 重いとき・VR に入ると真っ暗なとき

Pimax は視野が広いぶんレンダーターゲットが巨大になります。**まず実測を見てください。**
VR を終了すると、画面下にそのセッションの実測値が出ます。

```
VR 実測: 38fps / フレームバッファ 5472x2736（15.0Mpx）
解像度が大きすぎます。?scale=0.8 を試してください。
```

ヘッドセットを被っている間は画面の文字が読めないので、終了時に残す作りにして
あります。VR 内で見たい場合は `?debug` を付けると、左手のパネルに fps と
フレームバッファのサイズが出ます。

目安として、90fps を保てるのはおおむね **900 万ピクセル／フレーム**までです。
これを超えているなら、まず解像度を落とすのが圧倒的に効きます（描画コストは
ピクセル数にほぼ比例するため）。効く順に:

```
http://localhost:8080/?scale=0.7      # XR のレンダー解像度。いちばん効く
http://localhost:8080/?shadow=1024    # 影の解像度を落とす（既定 2048）
http://localhost:8080/?shadow=off     # 影を切る
http://localhost:8080/?quality=0.5    # テクスチャ解像度を半分に（起動も速くなる）
http://localhost:8080/?safe           # 上を全部まとめた最小構成
```

### コントローラーが効かないとき

`?debug` を付けると、左手コントローラーにデバッグパネルが出ます（PC では **D キー**でも切替）。

```
http://localhost:8080/?debug
```

`inputSources` の handedness / プロファイル名 / **axes と buttons の生の値** / 実 fps が
VR 内でそのまま読めるので、「スティックが別の軸に来ている」「handedness が none」といった
プロファイル差がその場で分かります。

コード側では次のフォールバックを入れてあります（`src/controllers.js`）。

- サムスティックは xr-standard の `axes[2]/[3]` を優先しつつ、`axes[0]/[1]` しか返さない
  コントローラーでも動く（倒れている方の軸ペアを採用する）
- `handedness` を返さないランタイムでは、1 本目を移動・2 本目を旋回として扱う

## Quest などスタンドアロン機で試す

ヘッドセット内のブラウザから開く場合は、WebXR が
**セキュアコンテキスト（HTTPS または localhost）** を要求する点だけ注意が必要です。
手軽な順に 3 つ:

1. **Quest を USB 接続して `adb reverse`**（おすすめ・追加設定なし）
   ```bash
   adb reverse tcp:8080 tcp:8080
   ```
   Quest のブラウザで `http://localhost:8080` を開く。

2. **GitHub Pages に公開する**
   `.github/workflows/pages.yml` を同梱しています。リポジトリの
   Settings → Pages で Source を「GitHub Actions」にすると、`main` への push で公開されます。

3. **トンネルサービス**（ngrok / cloudflared など）で HTTPS の URL を発行する。

このシーンは PCVR 向けの設定（影 4096、面光源、クリアコート）で作ってあるので、
Quest では次のあたりから落としてください。

```
http://localhost:8080/?shadow=1024&quality=0.5&scale=0.9
```

PC の Chrome で試すだけなら、[WebXR API Emulator](https://chromewebstore.google.com/detail/webxr-api-emulator/mjddjgeghkdijejnciaefnkjmkafnnje)
拡張を入れると ENTER VR が押せるようになります。

ゲームパッド（Xbox 配置）でも PC 版を遊べます：左スティック 歩く（LB で速く）、右スティック 見回す、
A 拾う / 投げる、B ラケットを置く、X カートの乗り降り、Y カートの視点、RB ラケットを振る、
RT / LT アクセル / ブレーキ、View BGM、Menu ハンコンの設定。ブラウザが「標準の配置」として出さない
パッド（名前がゲームパッドらしいもの）も使えます。そのときは A アクセル、B ブレーキです。

テーブルの上に**野球ボール**があります。つかんで投げると、キャラクターが目と首で追いかけます。
手前には**ラケットとテニスボール**も置いてあります（テニスの項）。

正面の窓は**掃き出し窓**（引き戸を開けた状態）なので、そのまま**庭へ歩いて出られます**。
柵の中央が空いていて、飛び石が芝生まで続いています。

### 庭でキャッチボール

庭へ出ると、女の子もついてきて、4.5m ほど離れて構えます。ボールを投げると、軌道を
先読みして走り込んで捕り、振りかぶって投げ返してきます。捕り損ねた球やゴロは、
転がった先でしゃがんで拾います。

- 地面に落とさずに続いた回数が、女の子の頭の上に **ラリー / ベスト** として出ます
- ラリーが続くと、1 回ごとに 20cm ずつ離れていきます（最大 6.3m）。落とすと元の距離へ
- 女の子のほうへ投げた球は、向きと高さを少しだけ相手へ寄せます（VR は半分、PC は届く球筋まで）
- 速い球、高すぎ / 低すぎる球、走り込みが間に合わない球は、ときどき手からこぼします
- キャッチボール中はこちらの顔を見ていて、投げ返した球をこちらが受けると、にっこり笑います
- 部屋へ戻ると、女の子も少しあとで戻ってきます

### テニスコート

庭の遊具のさらに奥（家から 13〜30m）に、テニスコートがあります。そのまま歩いて入れます。

- 大きさは子ども用のミニテニス（ITF レッド）規格の 12.8m × 6.0m、ネットの高さは中央 80cm
- 家から見てコートは縦長に置いてあり、窓からネットの向こうまで見通せます
- 奥に高さ 2.6m のバックフェンス、左右に 1m の柵。手前（家の側）には高さ 3m の防球ネットがあり、
  打ち損じた球が庭まで転がっていきません。ネットの右端 1.4m が入口です
- 手前のコートの左後ろ（防球ネットの前）に**ボールかご**があり、テニスボールが 12 個入っています。
  コートにも 3 個転がしてあります
  - VR：かごの中の球をそのままつかめます。球をかごの口へ落とすと、かごに入ります
  - PC：ラケットを持ってかごのそばで F を押すと、かごから 1 つ取り出します
- 転がった球がコートまで行ったときは、女の子がコートの中まで拾いに行きます
- ラケットを持って庭へ出ると、女の子もコートへ来ます（下の「女の子とテニス」）

### 女の子とテニス

**持っている道具で遊びが変わります。** ラケットを持って庭へ出ると、女の子もキャッチボールをやめてコートへ来て、
向こう側のネットポストの脇に置いてある自分のラケット（ピンク）を拾い、ベースラインの少し内側で構えます。

- 飛んできた球の軌道を先読みして（空気抵抗・回転・弾み方まで）、1 回弾んだあと打ちやすい高さに
  来る点を選び、そこへ走って打ち返します。体の右側ならフォアハンド、左側なら両手打ちのバックハンド
- 振りはテイクバック → ラケットの先を落とす → インパクト → フォロースルーの手続きのモーションで、
  実際にラケットが球に当たったときだけ返ります（間に合わなければ空振り）
- 打ち返す球は、プレイヤーの 1.8m ほど手前に弾むように狙います
- 自分の側に止まった球は拾いに行き、自分で落として打って送ってきます
- ラケットを置く（か部屋へ戻る）と、ラケットを元の場所へ戻し、ネットの脇を回ってキャッチボールに戻ります

ラリー：

- 打った球が相手のコートに入るたびに 1 つ数え、ネットの上に **ラリー / ベスト** を出します
- ネット・アウト（線の上は入り）・2 回弾む（返せなかった）・手で取ると途切れ、女の子が理由を言います
  （「アウトー！」「あー、ネット！」「ドンマイ！」、自分のミスなら「ごめん、ながすぎた！」など）。
  5 回ごとに「10 かい、つづいたよ！」と数えて、にっこりします
- 女の子もときどきミスをします（ネットか、長すぎ / 横へ外れる）。速い球・バックハンド・長いラリーほど増え、
  ラリーが続くと返球も少しずつ速くなります
- プレイヤーの打球は、相手のコートへ向かっている球だけ、落ちる所を少しコートの内側へ寄せます
  （VR は 35%。PC は振りの向きを加減できないので、いつも返しやすい深さと速さに直します）
- PC ではスペースを押したままにすると振りかぶって待ち、飛んできた球が届く所へ来たら自動で振ります
  （面の位置も球の通り道へ寄せます）

### ラケットとテニスボール

テーブルの手前にラケット（全長 70cm）とテニスボールがあります。

- VR では、ラケットをどこでつかんでもグリップを握った形で手に収まります（面は手のひらと同じ向き）。
  反対の手でテニスボールを持ち、トスして打てます
- PC では F でラケットを拾い、もう一度 F でテニスボールを拾います。スペースでトスして自動で打ちます
  （ボールを持っていないときは、スペースを押して振りかぶり、離して振ります）。G でラケットを置きます
- 打った球の速さと向きは、ラケットが実際に動いた速さと面の向きで決まります。
  面の中心（スイートスポット）ほどよく飛び、面の端では弱くなります。
  下から上へこすり上げるとトップスピンがかかり、打った球が沈みます
- テニスボールは野球ボールより軽く、空気抵抗が約 3 倍効きます。回転で曲がり（マグヌス効果）、
  弾むときに回転で向きと速さが変わります（トップスピンは前へ伸び、バックスピンは止まる）
- 弾む高さはコートがいちばん高く（2.54m から落として 1.37m）、室内の床、芝生の順に低くなります
- ネットに当たった球は、その場に落ちます

### カート

庭の右（テニスコートの横）にカートコースがあります。スタートの枠に青いカート（プレイヤー）と
ピンクのカート（女の子）が並んでいます。

プレイヤーがカートに乗ると、女の子も遊びをやめて歩いてきて、ピンクのカートに乗って走り出します
（コースの少し先を狙ってハンドルを切り、曲がりの手前でブレーキを踏みます）。プレイヤーが降りて
しばらくすると、女の子もカートを止めて降り、キャッチボールに戻ります。2 台がぶつかると押し合います。
脚はダッシュボードの下に入るので、短いスカートでも中は見えません。

#### レース

1. カートに乗ると、女の子もピンクのカートに乗って、自分のスタートの枠で待ちます
2. プレイヤーもスタートの線の後ろ（8m まで）に止まると、1 秒ほどでスタートの合図が始まります。
   ゲートの 3 つの灯りが 1 秒ごとに赤く点き（ピッ）、全部が緑になったら（ポーン）スタート。
   合図のあいだは、どちらのカートも動きません
3. 3 周のレース。画面の右上（VR と一人称ではダッシュボードの小さな画面）に、周回・順位・タイムが出ます
4. ゴールすると結果が出て、女の子は自分の枠へ戻ります。また枠に止まれば、次のレースが始まります

- 女の子は、抜いた・抜かれた・最後の周・勝ち負けでしゃべります
- 女の子のペースは、ひとりで走って 3 周 34.3 秒ほど（ピンクのカートは青より速くしてあります）。
  前にいても手加減はしません。後ろに離れたときだけ追い上げ、すぐ後ろに追いつくと横へ出て抜きにかかります
- **ハンドブレーキ**（後輪だけのブレーキ）：引くと減速し、ハンドルを切っているとお尻が流れて回り込みます
- 途中でカートを降りると、レースはやめになります

- コースには少し上り下りがあります（右奥のコーナーへ 1m ほど上って S 字で下り、奥でもう一度小さく上る）。
  スタート / ゴールの前後は平らです。上りでは遅く、下りでは速くなり、カートは坂に合わせて傾きます。
  路面のまわりは土手になっていて、歩いて（PC も VR も）上り下りできます
- 最高速は時速 29km ほど。芝生へ出ると遅くなり、速いほどハンドルが切れにくくなります
- ブレーキで止まり、止まってからも踏み続けるとバックします
- 壁に正面から当たると止まり、斜めに当たれば壁に沿って滑ります

#### ハンコン・ペダル

ハンドル型コントローラー（Logitech、Thrustmaster T300 / T-GT、Fanatec、CAMMUS などの DD）と、
SIMJACK などの単体のペダルが使えます。ハンドルとペダルが別々の機器でも大丈夫です。
PC につないでおけば、VR の中でも使えます。

1. **H キー**で設定を開き、「キャリブレーションを始める」
2. 案内に沿って、ハンドルをまっすぐ →「次へ」→ 左いっぱい → 右いっぱい → 真ん中
3. アクセルを踏みきって離す、ブレーキを踏みきって離す
4. バーでハンドル・アクセル・ブレーキが動くのを確かめる

- ペダルは、キャリブレーションの途中で初めて踏んでも拾います（Chrome は機器を一度動かすまで見せません）。
  「アクセルだけ覚え直す」「ブレーキだけ覚え直す」で片方だけやり直せます
- **割り当て**：ハンドル・アクセル・ブレーキごとに、機器と軸を選べます（ペダルは離した状態で選ぶ）。
  「離した値を記録」「踏みきった値を記録」「反転」で手で合わせられます
- ペダルが一覧に出てこない（Gamepad API に出ない）ときは、「HID で直接つなぐ」でペダルを選ぶと、
  WebHID で直接読みます（Chrome / Edge。一度選べば次からは自動でつなぎます）
- **ハンコンのボタン**：「乗る / 降りる」「視点」「設定の画面」「ハンドブレーキ」を、ハンコンのボタンに
  割り当てられます（「覚える」を押してからボタンを押す）。HID でつないだハンコンのボタンも使えます
- **ハンドブレーキ**：レバー型（LTB-HandBrake など）は「ハンドブレーキを覚える」か割り当てで。名前が
  ハンドブレーキの機器は自動で使います
- VR のコントローラー（Pimax P2N など）は、ブラウザの一覧に出てきても、ハンコンの候補から外します
- **設定の保存**：割り当て・キャリブレーション・ボタン・FFB の設定は、このブラウザ（localStorage）に
  自動で保存され、次に開いたときも使えます。「設定を書き出す」で控えを取り、別のブラウザで
  「貼り付けた設定を読み込む」で戻せます
- ハンコンをつないでいても、キーボード（W アクセル、S ブレーキ、A / D ハンドル）とゲームパッドで運転できます

「ハンドルいっぱいまでの角度」（何度回すとカートのハンドルがいっぱいか、既定 90°）と、
「ハンコン全体の回転角」（ハンコン側の設定に合わせる。G29 / T300 は 900°）も変えられます。

**FFB**（実機では確かめていません）：Chrome / Edge で、設定の「FFB を有効にする」からハンコンを選ぶと、
速いほど重くなるセンタリング・縁石のガタガタ・芝生のざらつき・ぶつかったときの反動を出します。

- Logitech（G29 / G27 / G25 / Driving Force）は Logitech の命令、それ以外（CAMMUS などの DD、
  Thrustmaster、Fanatec）は HID 標準の FFB（PID）の命令で試します
- Thrustmaster と Fanatec は、機器が標準の命令を受けないことがあります。動かないときは
  「機器の情報を書き出す」の内容を送ってもらえれば、それに合わせて直します
- G920 / G923 の Xbox 版は、別の命令なので動きません
- CAMMUS DDWB は、書き出してもらった報告の形に合わせてあります（効果の種類の並びの食い違い、
  軸の有効化が X 軸で書かれていること、力の向き 90° など）。実機ではまだ確かめていません

### 女の子の声

**VOICEVOX の声**（おすすめ）：[VOICEVOX](https://voicevox.hiroshiba.jp/)（無料）で、台詞を前もって音声ファイルにしておくと、
その声でしゃべります。口の動きも声にぴったり合い、声は女の子の頭の位置から聞こえます（VR では向きで聞こえ方が変わります）。

1. VOICEVOX をインストールして起動する（起動しているあいだ、PC の中で VOICEVOX エンジンが動きます）
2. このリポジトリで `npm install`（初回だけ。MP3 にする lamejs が入ります）
3. 声を選ぶ：`node scripts/voicevox.mjs --samples` で、候補の声の見本が `voices/samples/` にできます。
   `npm start` で開いて http://localhost:8080/voices/samples/ で聞き比べます（`--list` で全部の声の番号も出ます）
4. 台詞を作る：`node scripts/voicevox.mjs --speaker 番号`（既定は 8 = 春日部つむぎ ノーマル）。
   約 470 本（数の入った台詞も、ゲームで出る数のぶん）を作り、`voices/voicevox/` に MP3（合わせて 4MB ほど）と
   `manifest.json`（台詞 → ファイル・長さ・拍ごとの母音と時間）を書きます。数分かかります
5. `voices/voicevox/` をコミットする（公開しているページにも入ります）

- 話し方は `--speed 1.08 --pitch 0.02 --intonation 1.25` で変えられます。台詞を足したり直したりしたら、もう一度実行すると
  変わった台詞だけ作り直します
- VOICEVOX の利用規約で、声を使うときは「VOICEVOX:キャラクター名」の表記が要ります。開始画面の「女の子の声」の欄に出ます。
  キャラクターごとの規約（商用・表記のしかたなど）も、VOICEVOX のサイトの各キャラクターのページで確かめてください
- 用意していない台詞（想定より大きいラリーの数など）は、ブラウザの音声合成で読みます。ポケバイの秒は声では整数に丸め、
  釣りの魚は声では名前だけ言います（吹き出しには 19.4 秒・大きさまで出ます）
- **V キー**で VOICEVOX の声とブラウザの声を切り替えられます。`?voice=tts` でいつもブラウザの声にできます

**ブラウザの音声合成**：VOICEVOX の声を作っていないときは、ブラウザの音声合成（Web Speech API）で短い台詞をしゃべり、台詞に合わせて口が動きます。
頭の横に吹き出しも出るので、声の出ない端末でも分かります。

- 声の種類は端末に入っている日本語音声しだいです（Windows の Chrome なら Nanami / Haruka など）
- 日本語の声が端末に無いときは読み上げません（英語などの声だと片言になるため）。台詞は吹き出しだけになり、
  開始画面に日本語の声の入れ方が出ます（Windows は［設定］→［時刻と言語］→［言語と地域］→［日本語］の
  ［言語のオプション］で「音声合成」を追加。Microsoft Edge か Google Chrome なら最初から日本語の声があります）。
  開始画面には、いま使っている声の名前も出ます
- ブラウザの決まりで、ページを一度クリックする（キーを押す、ENTER VR を押す）までは声が出ません
- `?voice=off` で声だけ止められます（吹き出しと口の動きは残ります）
- 若い女性の自然な声（Edge の Nanami（Natural）など）を優先し、声ごとに高さと速さを合わせています。
  **V キー**で、端末に入っている日本語の声を順に試せます（「このこえ、どうかな？」と言い、吹き出しに
  声の名前が出ます）。選んだ声は覚えておきます。`?voicepitch=1.3&voicerate=1.1` で高さと速さも変えられます

### BGM

外部の音源は使わず、ブラウザの中で曲を合成して流しています（へ長調・76BPM のオルゴール風、約 50 秒でループ）。
女の子がしゃべっているあいだは音量が下がります。

- ページを一度クリックする（キーを押す、ENTER VR を押す）と鳴り始めます
- **M キー**でオン / オフ
- `?bgm=off` で最初から消す、`?bgm=0.2` のように数字で音量（既定 0.35）

右の壁のスイッチ 3 つで、時間帯（昼 / 夕 / 夜）が切り替わります。

### URL オプション

| | |
|---|---|
| `?perf` | 右下に fps / 解像度 / GPU を出す |
| `?dpr=1` | devicePixelRatio の上限（既定 2）。高 DPI 機の負荷を揃えるのに使う |
| `?safe` | 切り分け用の最小構成（影・環境マップ off、テクスチャ 1/4、解像度 0.7） |
| `?scale=0.8` | XR のレンダー解像度倍率 |
| `?shadow=1024` | シャドウマップの解像度（既定 2048）。`?shadow=off` で影を切る |
| `?quality=0.5` | 手続きテクスチャの解像度倍率（起動時間に効く） |
| `?cull=off` | 視錐台カリングを完全に切る（外縁が欠けるヘッドセット向け） |
| `?bob=0.5` | 歩行時の頭の上下動の強さ（既定 1、`?bob=0` で切る） |
| `?mute` | 足音を鳴らさない |
| `?sit=off` | キャラクターをソファに座らせない |
| `?debug` | VR 内にデバッグパネルを出す（PC では D キーでも切替） |
| `?vrm=./models/other.vrm` | 読み込む VRM を差し替える（既定 `./models/character.vrm`） |
| `?walk=off` | キャラクターを歩かせず、その場に立たせる |

## キャラクター（VRM）

部屋を歩いているのは `models/character.vrm`（このリポジトリのオーナーが自作した
VRM 1.0 モデル）です。リポジトリで唯一のバイナリアセットで、15MB ほどあります。

読み込みは非同期なので起動は待たせません。ファイルを消した場合はキャラクターが
居ないだけで、部屋はそのまま動きます。

別のモデルを試すときは `models/` に置いて URL で差し替えられます。

```
http://localhost:8080/?vrm=./models/another.vrm
```

### なぜ素の GLTFLoader ではなく three-vrm なのか

VRM は glTF の拡張なので `GLTFLoader` だけでも「読めて」しまいますが、それだと
こうなります。

- **MToon マテリアルが unlit に落ちる** … 部屋の光を拾わないので、昼でも夜でも
  同じ明るさの板が立っているように見える
- **髪や服が揺れない**（`VRMC_springBone`）
- **視線が動かない**（`VRMC_vrm` の lookAt）

この 3 つは [@pixiv/three-vrm](https://github.com/pixiv/three-vrm)（MIT）を
`GLTFLoader` にプラグインとして挿すだけで解決します。`vendor/three-vrm/` に
同梱してあるので、追加のインストールは要りません。

```js
const loader = new GLTFLoader();
loader.register((parser) => new VRMLoaderPlugin(parser));
const vrm = (await loader.loadAsync(url)).userData.vrm;
```

残りは `src/character.js` の仕事です。

- **T ポーズをほどく** … 正規化ボーン（humanoid の normalized rig）に角度を入れる。
  腕を下ろし、肘と指を少し曲げるだけで人形っぽさが消えます
- **呼吸と重心の揺れ** … 周期の違う sin を 2 本重ねる。棒立ちは 3D だとすぐ
  人形に見えます
- **まばたき** … `expressionManager.setValue('blink', …)` を 2〜6 秒に 1 回
- **視線** … `vrm.lookAt.target = camera`。XR 中もカメラの `matrixWorld` は
  WebXRManager が更新してくれるので、PC と VR の両方でこちらを見ます
- **カリングから外す** … スキニングしたメッシュのバウンディングは当てにならず、
  `main.js` のバウンディングスフィア膨張も読み込み前に終わっているため

毎フレーム `vrm.update(dt)` を呼ぶのを忘れないでください（スプリングボーン・
視線・表情がまとめて進みます）。`src/world.js` の `update()` から呼んでいます。

### 歩きと座り（モーションデータなし）

このモデルにアニメーションは入っていません。部屋のテクスチャと同じで外部
アセットは増やしたくないので、**歩き・立ち・座りはすべてコードで作っています**
（`src/character.js`）。要るのは次の 4 つだけです。

**1. ポーズを 2 つ持って混ぜる。** `STAND_POSE` と `SIT_POSE` は正規化ボーンの
角度表で、`sitAmount`（0..1）で線形に混ぜます。座る / 立つはこの値を
1.6 秒かけて動かすだけで、遷移のアニメーションを別に作る必要はありません。

**2. 歩きは位相 1 本。** 腿・膝・足首・腕・腰の上下と傾きを、すべて同じ `phase`
の sin / cos から作ります。膝は遊脚のあいだだけ曲げます（接地しているほうを
曲げると膝が抜けて見える）。

**3. 位相は時間ではなく「進んだ距離」から進める。** ここが足の滑りの分かれ目です。

```js
phase += Math.PI * movedDistance / stride;
```

時間で回すと、速度が変わったときや旋回中に接地した足が床を滑ります。距離で
回せば歩幅が一定になるので、滑りません。歩幅はモデルの腰の高さから決めるので、
背の低いキャラクターは自然と小刻みに歩きます。

**4. 経路は節点のループ。** テーブルと椅子・ソファ・本棚を避けた 7 点の閉ループ
（`ROUTE`）を順に辿ります。家具は動かないので、経路探索も当たり判定も要りません。
到着するたびに「次の節点へ行く / 立ち止まる / ソファに座りにいく」を選ぶ
小さな状態機械です。

```
idle ──→ walk ──→ turn ──→ sitDown ──→ sit ──→ standUp ──┐
 ↑         │                                              │
 └─────────┴──────────────────────────────────────────────┘
```

座る位置は**モデルの腿の長さから決めています**。このモデルは身長 1.4m しか
なく、大人用のソファ（座面 61cm）の奥に腰を下ろすと脛がクッションに埋まります。
膝が座面の前縁あたりに来るように浅く腰かけさせ、足はぶら下げます。

歩かせたくないときは `?walk=off` で、その場に立たせられます。

### モデルのライセンス

VRM にはモデルごとのライセンスがファイル自身に埋め込まれています
（`VRMC_vrm.meta`）。同梱の `character.vrm` は作者本人がこのリポジトリに置いた
ものですが、メタデータ上は **再配布（`allowRedistribution`）と改変
（`modification`）が不可、商用利用は不可（`personalNonProfit`）、作者表示が必要
（`creditNotation: required`）** になっています。フォークして再公開する場合は
このファイルを差し替えてください。

他所から持ってきたモデルを置くときも同じで、**再配布不可のモデルをリポジトリに
入れて GitHub Pages で公開するのは再配布にあたります**。その場合は
`.gitignore` に `models/*.vrm` を足して、手元に置くだけにしてください。

作者表示は、読み込みに成功したら `meta` の名前と作者を画面左上に出すように
してあります（`src/main.js`）。

## 画質のつくり方

「リアルに見えるかどうか」はレンダラーの性能よりも、**ライティングの組み立て方**と
**テクスチャの縮尺**でほとんど決まります。このシーンで効かせているのは次の 6 つです。

### 1. 環境マップを部屋自身から焼く

一番効きます。`PMREMGenerator.fromScene()` で**部屋そのもの**をキューブマップに
撮り、`scene.environment` に戻しています（`src/lighting.js`）。壁の照り返しが金属や
クリアコートに映り込むようになり、間接光をベイクしたのに近い効果が、
アセットなしで手に入ります。照明を変えたときだけ焼き直します。

```js
envTarget = pmrem.fromScene(scene, 0, 0.1, 1000, { size: 256, position: ENV_PROBE });
scene.environment = envTarget.texture;
```

### 2. 窓は面光源、影は平行光

窓の開口と同じ大きさの `RectAreaLight` を置いています。点光源や平行光では
「窓際だけ柔らかく明るい」減衰が出ません。ただし three.js の RectAreaLight は
**影を落とせない**ので、影は別に `DirectionalLight`（太陽）が担当します。
この 2 本立てが室内ライティングの定石です。

### 3. テクセル密度をメートルで揃える

`tex.material('walnut', { sizeX: 0.45 })` の `sizeX` は「その部材が実寸で何メートルか」。
テクスチャ側は 1 タイル何メートルかを持っているので、割り算で繰り返し回数が決まり、
部屋じゅうで木目の細かさが揃います。

同じマテリアルを天板にも椅子の脚にも使い回すと、小さい部材ほど木目が細かくなりすぎて
**くしゃくしゃの箔**のように見えます。最初の実装はまさにこれで失敗しました。

### 4. ノーマルマップを強くしすぎない

CG っぽさの最大の原因です。塗り壁の `normalScale` は 0.18、凹凸の周期は 8mm。
これより粗く・強くすると、たちまち「吹き付け塗装」になります。
さるすべりの樹皮に至っては、つるつるなのが特徴なのでほとんど凹凸を付けていません。

### 5. 壁に厚みを持たせる

壁は厚さ 14cm の押し出しで作り、窓とドアは穴として開けています。開口部の
**見込み（reveal）** が出るかどうかは大きく、板 1 枚に穴を描いただけの窓は
立体視だと厚みの無さが即バレします。

### 6. 窓の外に世界を作る

室内の写実は「窓の外に本当に奥行きがあるか」でかなり決まります。
テラス → 柵 → 芝生 → さるすべりと滑り台 → 遠景の生垣と木立、と層を重ね、
霧（`scene.fog`）で遠くを空の色に溶かして大気遠近を出しています。

### やっていないこと（WebXR の限界）

- **ポストプロセス**（SSAO / Bloom / 被写界深度）。`EffectComposer` は WebXR の
  ステレオ描画と素直に噛み合いません。トーンマッピング（ACES）はマテリアル側の
  処理なので効いています。
- **SSR / リアルタイム GI**。環境マップの焼き直しで代用しています。
- **本物のガラス**。`MeshPhysicalMaterial.transmission` は専用の描画パスが要るので、
  ごく薄い加算のツヤだけ置いて「そこに板ガラスがある」ことを示しています。

ここから先（ベイクした GI、SSAO、実測の PBR テクスチャ）に進みたい場合は、
Unity URP + ライトマップベイクに移すのが現実的です。

## 歩いている感じのつくり方

床をどれだけ作り込んでも、移動が等速の水平スライドだと「浮いている」ように
しか感じられません。接地感は次の 4 つで作っています（`src/controllers.js`）。

### 1. 歩幅に応じた頭の上下動

人が歩くとき、頭は 1 歩ごとに 2〜3cm 沈みます。これが無いのが「フワフワ」の
最大の原因です。位相は**時間ではなく進んだ距離**で回します。時間で回すと
ゆっくり歩いても同じ間隔で沈んでしまい、歩幅と合いません。

```js
stepDistance += speed * dt;
const phase = (stepDistance / STEP_LENGTH) * Math.PI;
bob.position.y = -Math.abs(Math.sin(phase)) * BOB_HEIGHT * gait;
```

揺れは `player` を直接動かさず、`bob` という子の Group に持たせています。
`player.position` は移動・スナップターン・壁の押し戻しが取り合うので、
そこに揺れを足すと互いに干渉します。カメラも手もこの下にぶら下げてあるので、
体ごと沈む動きになります。

VR での上下動は酔いにつながるので、`?bob=0.5` で弱めたり `?bob=0` で
切ったりできます。

### 2. 加減速

スティックの入力を速度そのものにせず、「寄せていく目標」として扱い、
一定の加速度で近づけます。瞬時に最高速へ飛ぶと、床を蹴っている感じが出ません。
止まるほうを速くしてあるのは、入力を放したあともずるずる進むと操作感が
悪くなるためです。

### 3. 足音

`src/audio.js` で WebAudio から合成しています（音も外部アセットを持ちません）。
木の床の足音を「低い正弦波の打撃」「ローパスした減衰ノイズ」「高域の擦れ」の
3 つで組み立て、1 歩ごとに周波数と音量を少しずつ変えています。まったく同じ音が
続くと、逆に「録音を貼っている」ように聞こえます。

### 4. 足元の影

VR で下を見ると体がないので、自分が床の上にいる手がかりがありません。
柔らかい楕円を頭の真下に敷き、沈み込みに合わせて少し濃くしています。

## つくり変えるヒント

- **小物を増やす** → `src/furniture.js` の `PROPS` に素材を足すだけで、
  つかめる小物が増えます。
- **新しいマテリアル** → `src/textures.js` に `bake(size, shade, strength)` を使った
  レシピを 1 つ足して `sets` に登録します。`shade` は UV を受けて
  アルベド / 高さ / AO / ラフネス / メタルネスを書くだけの関数です。
- **公園に遊具を足す** → `src/park.js` の `sweepProfile()`（断面をカーブに沿って
  掃引する）と `taperedTube()`（半径の変わる筒）が使えます。滑り台のシュートと
  木の幹はこれで作っています。
- **時間帯を足す** → `src/themes.js` にもう 1 つ定義を書けば、壁のスイッチが
  自動で増えます。
- **3D モデルを置く** → `GLTFLoader` は `vendor/` に同梱済みです。
  `src/character.js` と同じ要領で読み込んでシーンに足せます。
- **キャラクターの歩く経路を変える** → `src/character.js` の `ROUTE`（節点を
  並べた閉ループ）。ポーズは `STAND_POSE` と `SIT_POSE`、歩きの振り幅は `GAIT` です。
- **座れる場所を増やす** → `SEATS` に座面の位置・高さ・向きと、そこへ入る
  経路の節点を足します。
- **ハンドトラッキング** → `renderer.xr.getHand(i)` と `XRHandModelFactory` を使います。
